## Ranked reviewer requests

1. **Seed replication.** "One chain per cell: H1/H2 compare two single trajectories. The document bootstrap captures measurement noise only, so every CI is anti-conservative, and the permutation test in 01 §Analysis has exactly two labelings. Run ≥3 seeds (sampling and training) for at least the REPLACE pair and report between-seed variance." Validity: any BN–EN slope difference is otherwise indistinguishable from seed noise. **(A)** 2.58 h per extra REPLACE chain (gen-0 reused): 2nd-seed pair 5.2 h, 3rd-seed pair +5.2 h (6 chains give 20 labelings, min one-sided p = 0.05). Full second seed of all six chains = 31.7 h (unaffordable). Pre-empt: add a `--seed-offset` to `run_chain.py`; run the 2nd-seed pair unconditionally; file a DECISION to cut FILTER to G = 3 (saves 8.3 h) to fund the 3rd seed; rewrite 01 to drop "permutation" unless ≥3 seeds exist.

2. **No-synthetic control.** "Add one chain per language trained with the identical recipe on real data at every generation (REAL-REPEAT: the seed again; better REAL-FRESH: 10M new human tokens) so drift from continual fine-tuning at lr 2e-4 is separated from recursive collapse." Validity: REPLACE perplexity rise (H0, H1) is otherwise confounded with recipe drift/forgetting. **(A)** ≈ 0.26 h/step (no 10M generation) → 1.6 h/language, 3.1 h total; REAL-FRESH needs 60M extra cleaned tokens per language (CPU only). Pre-empt: run REAL-REPEAT; REAL-FRESH if Sangraha/FineWeb slices suffice.

3. **Compute/exposure confound in ACCUMULATE.** "ACCUMULATE at g trains from the previous checkpoint on seed + all synthetic (`run_chain.py` 179, 206–213), so at g = 6 it has had 7 epochs over the real seed and ~7× REPLACE's optimizer steps; H2 and H0's '50 % smaller' criterion conflate data composition with compute. The anchor papers re-initialise from the pretrained model each generation; this design is continual — verify and state." **(D, optional A)** Compute-matched REPLACE or re-init ACCUMULATE ≈ 6.6 h/chain, 13 h/pair — unaffordable. Pre-empt: the REAL-REPEAT control (#2) isolates re-exposure; define the estimand in 01 as "accumulation as practised (continual)"; report cumulative train tokens per chain-generation from `step.json`.

4. **Cross-language comparability of metrics and budget.** "Per-token log-perplexity and distinct-2 are not on the same scale across languages (Gemma fertility for BN ≈ 2–3×; agglutination raises type counts); 10M BN tokens carries fewer words/bytes than 10M EN. Report bits-per-byte, slopes normalised to gen-0, bytes/words per corpus, and justify the token budget." Validity: raw slope comparison (H1) can be a scale artefact. **(C)** for normalised slopes; **(B)** for BPB unless per-document NLL, token and byte counts are written now (`metrics.py` 62–67 keeps only means). Optional **(A)**: EN-REPLACE at the token count matching BN's word count (~4M tokens, ≈ 1.0 h). Pre-empt: write `heldout_nll.jsonl` per generation; pre-register normalised slope as co-primary; run the 1 h EN chain.

5. **Probe validity (floors, length bias).** "Show gen-0 and base-model tail-fact recall exceed chance (25 %) per stratum with CIs, otherwise H1(iii) cannot decline; sequence log-likelihood (`metrics.py` 79–80, 95) favours shorter objects, and BN objects vary more in token length — pre-specify a length-controlled rule." **(B→C)** if per-option log-probs and token counts are stored; base-model metrics ≈ 0.1 h/language. Pre-empt: store per-option scores; add a base-model `compute_all` call (none exists in `run_chain.py`); pre-register a floor rule (stratum excluded if gen-0 CI includes 0.25).

6. **Inference and decision rules.** "State the unit of inference, smallest effect of interest, decision rule (all three metrics or any), and that one chain per cell supports no population claim; pre-specify the functional form — collapse trajectories are non-linear, so OLS over 7 points is a choice, not a given." **(D/C)** Pre-empt: rewrite 01 §Analysis and 07 §3; add log-ratio-to-gen-0 at g = G as a pre-specified alternative estimand.

7. **Archive every checkpoint and corpus.** "Only final checkpoints are pulled (`04` §4b `--checkpoints final`); every later re-analysis is then impossible." **(B enabler)** 38 checkpoints × 0.54 GB fp16 ≈ 21 GB (`run_chain.py` 70 saves fp32 ≈ 41 GB); 36 corpora ≈ 3 GB. Pre-empt: `pack_results.py --checkpoints all`, fp16 copies, plus `sample.jsonl`, `synthetic*.jsonl`, prefixes, per-doc NLL and per-probe score files.

8. **Held-out contamination.** "The base model has seen Wikipedia and FineWeb-like text; held-out perplexity is partly memorised; id-disjointness (02 §2, `test_sanity`) does not remove near-duplicates between seed and held-out." **(C/D)** Pre-empt: MinHash cross-dedup seed↔held-out at Gate 1 (CPU); make fresh-slice perplexity co-primary; fix bug B3 below so the fresh slice is scored at all.

9. **Filter asymmetry.** "Script ≥ 0.95, 4-gram repetition ≤ 0.2 on whitespace words and a 40-word exact-match dedup are not equally stringent in BN and EN; differential pass rates confound filter with language." **(C/D + code fix)** Pre-empt: implement the pre-registered MinHash 0.8 dedup; verify `script_ratio` ignores digits/punctuation (Bangla text legitimately contains Latin digits); pre-register a rank-based (top-k %) filter as alternative.

10. **Generation count.** "G = 6 may end before REPLACE plateaus; extend to 8." **(A)** REPLACE only: 2 × 2 × 0.43 = 1.7 h; all chains +16.6 h (no). Pre-empt: declare REPLACE g = 7–8 as exploratory before the first chain starts (chains.yaml rule).

11. **Seed-corpus domain match.** "FineWeb-Edu is classifier-filtered educational text; Sangraha verified is general web/news/books. The cleaner EN seed can by itself slow collapse." **(D, or CPU swap at Gate 1)** Pre-empt: use a non-edu FineWeb slice, or report seed-quality proxies (repetition, base-model perplexity) per language and state the limitation.

12. **Prefix leakage.** "Every synthetic document begins with 16 real tokens (`run_chain.py` 92, 110): ~0.6M real tokens (~6 %) in each REPLACE training set, contradicting Brief §7.5, and the same 10,000 prefixes recur ~4× per generation; tail-mass and script metrics inherit a constant floor." **(D + C)** Pre-empt: train on continuations only, or state it; compute sample metrics on continuations (prefix recoverable via `prefix_id`).

13. **H3 and decoding sensitivity.** "ByT5 vs Gemma confounds architecture, pretraining data and tokenizer; top-p sampling may change collapse rates." **(D; A = 5.2 h for a top-p REPLACE pair)** Pre-empt: scope both out explicitly in 01.

Budget if 1 (2nd seed), 2, 4 (1 h chain), 5, 10 are added: ≈ 32.2 + 5.2 + 3.1 + 1.0 + 0.3 + 1.7 ≈ 43.5 h, inside the 55 h cap only if Gate-3 throughput matches the planner.

## Design flaws / bugs that would make results unpublishable as written

- **B1 Off-by-one in sample-based metrics.** `run_chain.py` 218–222: the 2,000-doc sample is drawn from `synthetic`, generated by the gen-(g−1) checkpoint, but recorded as generation g alongside perplexity/probes from the gen-g checkpoint. Gen-0's "sample" (line 160) is the real seed corpus, and the gen-G model's output is never measured. Distinct-2 slopes (primary) are shifted one generation and anchored on human text. Fix: after training, sample 2,000 docs from the new checkpoint (≈ 1–2 min); keep corpus statistics as a separate record.
- **B2 Case mismatch in tail mass.** `metrics.py` 156 lowercases seed types; 104/134 do not lowercase sample tokens. EN tail mass is biased downward (capitalised tokens never match); BN is unaffected — a language-asymmetric bias.
- **B3 Fresh slice dropped.** `metrics.py` 56 reads only the first 2,000 held-out docs; corpora.yaml defines 2,000 + 500 fresh. If fresh docs are appended, `log_ppl_fresh` is never produced.
- **B4 Filter deviates from pre-registration.** `run_chain.py` 142–145 exact 40-word match instead of MinHash Jaccard 0.8; 126 uses 300 held-out docs for the percentile band; 129 `except Exception` silently drops the perplexity criterion. Make it fatal.
- **B5 LR schedule mismatch.** `chains.yaml` `min_lr_ratio: 0.1` and 03 §2 "decay to 10 %" are not implemented; `run_chain.py` 60–64 uses plain cosine to 0.
- **B6 No CI on the primary diversity metric.** `metrics.py` 112–115 writes NaN CIs for distinct-n; tail-mass CI (135) resamples tokens, not documents. `analyze.py` must bootstrap from archived `sample.jsonl`; the random window start (109) must be pre-specified.
- **B7 "Token-level" perplexity is document-macro.** `metrics.py` 62–67 averages per-document mean NLL; 05 §1 promises token-level. Store per-doc totals and report both.
- **B8 fp16 with Gemma-3.** `chains.yaml` `dtype: float16` for a bf16-trained model risks inf/NaN logits in vLLM and scoring; the 4090 supports bf16 — switch and record.
- **B9 Fragile integrity count.** `run_chain.py` 211 `doc_id.split("-")[1]` raises on any id without a dash.
- **B10 Pre-reg inconsistency.** 01 promises a permutation test; 07 §3 uses only the paired bootstrap; neither is valid with one chain per cell (see #1, #6).
